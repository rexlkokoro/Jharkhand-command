01 — OVERVIEW

Mission Brief

What this platform is, who it's for, and why it exists.

Core Concept: Jharkhand COMMAND is a real-time geospatial intelligence platform that aggregates civic events, news signals, public incidents and government alerts across Jharkhand — then spatially plots, clusters, and visualizes them on an operational command-center dashboard. This is not a news website. It is a spatial intelligence and situational awareness system.
What It Is
  • A live interactive map intelligence system
  • A signal aggregation and geo-tagging engine
  • An event categorization and clustering system
  • A timeline-based situational replay tool
  • A district-level analytics command center
What It Is NOT
  • Not a news website or blog layout
  • Not a social media aggregator
  • Not a generic dashboard with charts
  • Not article-first or text-first UI
  • Not a consumer-facing product

02 — PRODUCT GOALS

Objectives & Event Types

Primary Goals
  • Aggregate Jharkhand signals from multiple sources in real-time
  • Auto-extract and geo-tag named locations using NLP
  • Plot, cluster, and categorize all events on a live map
  • Provide timeline-based event replay and trend analysis
  • Deliver operational situational awareness at district level
  • Enable search across people, places, keywords, and event types
Design Goals
  • Palantir/Gotham-inspired dark tactical UI aesthetic
  • Immersive, data-dense, cinematic experience
  • Map-first — the map is always the primary surface
  • No article or blog layout patterns whatsoever
  • Glowing markers, animated pulses, scanline effects
  • Modular dashboard widgets with layered panels

UI Zones Specification

Zone 1 — Main Map Canvas
Full-screen interactive map (Mapbox GL or Leaflet). Heatmap overlay layer. District boundary GeoJSON rendering. Animated event markers with glow pulses. Cluster groups at zoom-out. Time-based marker fade. Clickable markers → detail popover.
Zone 2 — Intelligence Feed Sidebar
Real-time scrolling event feed. Each item: category dot, location, headline, timestamp, confidence score. Color-coded by event type. Clicking an item flies the map to that location. Infinite scroll with 24h lookback window.
Zone 3 — Analytics Panel
Right panel: district stats, active incident counts by type. Mini bar charts for event density. Sentiment gauge per district. "Hot zones" ranked list. Collapses to icon strip on narrow viewport.
Zone 4 — Timeline Scrubber
Bottom bar: horizontal time scrubber with playback controls. Replay historical events as animated map sequence. Filter by date range. Escalation pattern visualization via event density spikes on the timeline track.
Zone 5 — Filter & Search Bar
Top command bar: keyword search + entity lookup (person/location). Filter toggles per event category (color-coded chips). District filter dropdown. Source filter. Active filters shown as dismissible tags.
Zone 6 — Event Detail Drawer
Slide-in panel on marker click. Shows: AI-generated summary, source links, extracted entities, location confidence score, related events, timeline of updates. Full NLP metadata exposed.

Returns aggregated grid data for heatmap rendering. Params: zoom_level, bbox, time_range.

/api/v1/events/clusters
Returns cluster centroids and counts for current viewport + filters.
GET
/api/v1/events/timeline
Bucketed event counts over time for timeline scrubber visualization.

Districts & Geo

GET
/api/v1/districts
All 24 Jharkhand district GeoJSON boundaries with current event counts.
GET
/api/v1/districts/{name}/stats
Per-district analytics: event breakdown by category, sentiment avg, top entities.

Search & Entities

GET
/api/v1/search?q={query}
Full-text + semantic search across events. Returns ranked results with snippet highlights.
GET
/api/v1/entities/{name}
Entity lookup — returns all events mentioning this person/place/org, with timeline.

Live Feed

WS
ws://api/v1/feed/live
WebSocket stream of new events as they are ingested and processed. Emits JSON event objects in real-time. Client subscribes with optional category/district filters.

08 — MAP INTERACTION DESIGN

Geospatial UX

Zoom Levels & Detail
  • Z5–8 — State view: Cluster bubbles, district heatmap, no individual markers
  • Z9–11 — District view: Large clusters break into sub-clusters, district label overlays appear
  • Z12–14 — City view: Individual event markers, category icons, animated pulses
  • Z15+ — Street view: Full detail markers, building-level precision, hover labels
Marker Interactions
  • Hover: expand marker, show mini tooltip (title + time)
  • Click: open EventDetailDrawer (slide in from right)
  • New events: animate in with radial pulse ring, 3s duration
  • Aged events: opacity decreases linearly over 24h window
  • Cluster click: zoom to cluster bounds
  • District click: highlight boundary, load district stats panel
Layer Controls
  • Heatmap toggle — density gradient overlay (red = dense)
  • District boundaries toggle — GeoJSON polygon layer
  • Category filter — show/hide marker types by category
  • Source filter — hide events from specific sources
  • Confidence threshold slider — filter low-confidence geotagged events
  • Satellite vs dark map tile toggle
Timeline Replay
  • Scrub through past 7 / 30 / 90 days
  • Play mode: events appear on map as animated sequence
  • Speed control: 1×, 5×, 10× playback
  • Heatmap evolves during replay showing density buildup
  • Escalation detection: burst alerts on event density spikes

09 — EVENT INGESTION PIPELINE

Data Flow Architecture

╔══════════════════════════════════════════════════════════╗ ║ INGESTION PIPELINE FLOW ║ ╚══════════════════════════════════════════════════════════╝ SOURCES (polled every 5 min via APScheduler) ├─ NewsAPI → query: "Jharkhand OR Ranchi OR Jamshedpur" ├─ GNews API → lang: hi + en, country: IN, region: Jharkhand ├─ RSS Crawler → Prabhatkhabar, JharkhandNews, Hindustan Jharkhand ├─ NDMA Feed → disaster / weather alerts (XML) └─ JH Govt Press → press.jharkhand.gov.in scraper ↓ raw articles collected → ingestion_queue (Redis) STEP 1: DEDUPLICATION → Compute sentence embedding (MiniLM-L6) → pgvector cosine similarity check (threshold: 0.92) → If near-duplicate exists → mark is_duplicate = true, skip STEP 2: JHARKHAND RELEVANCE FILTER → Check: does article mention Jharkhand districts/cities? → Regex + NER location check → Confidence < 0.4 → discard STEP 3: NLP PROCESSING (spaCy + HuggingFace pipeline) ├─ NER → extract PERSON, LOCATION, ORG entities ├─ Classification → DistilBERT → assign event category (11 classes) ├─ Sentiment → VADER + multilingual model → score -1 to 1 └─ Summarization → BART-large → 2 sentence summary STEP 4: GEOCODING → Extract primary location entity from NER output → Query Nominatim: "{location}, Jharkhand, India" → Fallback → Google Geocoding API → Store lat/lng as PostGIS POINT geometry → Assign to district via ST_Within() query STEP 5: STORE & BROADCAST → Insert into PostgreSQL events table → Update district stats cache (Redis) → Broadcast to WebSocket subscribers via Redis PubSub → Invalidate relevant API cache keys
Data Sources
NewsAPI GNews Prabhatkhabar RSS Hindustan Jharkhand NDMA XML JH Govt Press
Languages

Hindi (primary) and English both supported. mBART handles multilingual summarization. NER models fine-tuned on Hindi Jharkhand news corpus for place/person recognition accuracy.

Quality Gates
  • Relevance score ≥ 0.4 required
  • Geocoding confidence ≥ 0.5 required
  • Cosine similarity < 0.92 for dedup
  • Source allowlist enforcement

Scalable Deployment

╔═══════════════════════════════════════════════════════════╗ ║ PRODUCTION DEPLOYMENT ARCHITECTURE (AWS) ║ ╚═══════════════════════════════════════════════════════════╝ CDN LAYER CloudFront → static assets (Next.js build, GeoJSON, map tiles) Route 53 → DNS (command.jharkhand.app) COMPUTE LAYER (ECS Fargate — auto-scaling) ├─ web-service (Next.js) 2–8 tasks, 512MB RAM, 0.25 vCPU ├─ api-service (FastAPI) 2–8 tasks, 1GB RAM, 0.5 vCPU ├─ worker-service (Celery) 2–4 tasks, 2GB RAM, 1 vCPU └─ nlp-service (spaCy+HF) 1–2 tasks, 4GB RAM, 2 vCPU LOAD BALANCER ALB → api-service (HTTP/WS) ALB → web-service (HTTP) DATA LAYER ├─ RDS PostgreSQL 15 Multi-AZ, db.t3.large (dev) → db.r6g.large (prod) │ PostGIS extension enabled ├─ ElastiCache Redis cluster.t4g.micro → cluster.r6g.large │ Redis Streams for WebSocket pub/sub │ Redis Cache for API response caching (TTL: 30s) └─ S3 Raw article archive, NLP model weights SEARCH OpenSearch (managed) → entity search, full-text MONITORING CloudWatch → metrics & alerts Grafana → operational dashboards Sentry → error tracking (frontend + backend) SCALING RULES api-service: scale out when CPU > 70% OR p99 latency > 500ms worker-service: scale out when Celery queue depth > 50 tasks nlp-service: scale out when NLP queue > 20 items ESTIMATED COSTS (MVP, light traffic) ECS Fargate: ~$80/month RDS t3.large: ~$100/month ElastiCache: ~$30/month ALB + data xfer: ~$25/month OpenSearch (small): ~$50/month ───────────── Total MVP: ~$285/month
Performance Targets
  • API p95 latency < 200ms
  • WebSocket event lag < 1s
  • Map tile load < 500ms
  • Ingestion → visible on map < 60s
  • Support 500 concurrent users (MVP)
Reliability
  • 99.5% uptime SLA target
  • Multi-AZ database deployment
  • Redis Sentinel for failover
  • Graceful WebSocket reconnect
  • Dead letter queue for failed ingestions
Security
  • VPC private subnets for DB/Redis
  • IAM roles — least privilege
  • API key rotation for news sources
  • Rate limiting on all public endpoints
  • HTTPS/WSS only (TLS 1.3)
